# 前端设计规范

本文件用于本项目所有面向用户的页面。生成或修改任何页面前必须先读完本文件。
本文件描述的是**判断**，不是任务。具体做什么由每次的需求描述给出。

## 适用范围

产品是一个 AI 零代码应用生成平台。使用者是开发者和有一定技术背景的产品人员。
页面分两类，规则不同：

- **工作台类**（生成页、编辑页、应用列表、控制台）：使用者是来完成操作的。信息密度高，交互优先，减少装饰。
- **展示类**（落地页、应用详情、定价、文档）：使用者是来理解和判断的。留白优先，层级明确，一屏说清一件事。

判断不了属于哪类时，按工作台类处理。

## 优先级顺序

要求冲突时，按这个顺序保护：

1. 功能正确、数据真实、不编造任何界面上的数字和文案
2. 使用既有技术底座（见下节），不引入新依赖、不自造等价实现
3. 使用者当前要做的事一眼可见
4. 层级、排版、间距的一致性
5. 动效、细节打磨

第 5 条永远不能以牺牲第 3、4 条为代价。

只有在以下情况才停下来问：会影响数据含义、权限、计费、用户隐私、或需要我提供实际文案/素材。
其他情况按本文件的默认值执行，并在交付时说明你做了什么假设。

## 技术底座

只准使用以下这些。**不许自己写 CSS 文件，不许自定义字号、间距、颜色、圆角、阴影。**

- **框架**：React + TypeScript
- **样式**：Tailwind，只用工具类
- **组件**：shadcn/ui。组件源码在 `components/ui/`，写页面前先去读那个目录，确认组件是否已存在
- **图标**：lucide-react，统一 `size={16}`，特殊情况才用 20

需要的组件如果 `components/ui/` 里没有：先用 `npx shadcn@latest add <组件名>` 安装官方版本。
官方没有的，才允许用现有原语组合出来，**不允许从零手写一个已经存在的组件**（尤其是下拉、弹窗、菜单、表格、日期选择）。

不确定 shadcn/ui 或 Tailwind 的具体 API 时，去查当前文档，不要凭记忆写。

## 开工前先想清楚

写代码之前，先在心里（不要输出）回答：

- 谁会打开这个页面，他此刻要完成什么？
- 他最需要的那个操作或那条信息是什么？
- 页面上有什么是他不需要、但我正准备加的？

然后：**先说出这类页面最俗套的那个布局，再拒绝它**，除非内容确实需要它。
「居中大标题 + 一行副标题 + 三个图标卡片」是这个品类最常见的默认答案，默认不要用。

每个区块必须回答一个新问题。回答重复问题的区块合并掉。

## 视觉系统

### 排版

- 字号只用 Tailwind 的 `text-xs` / `text-sm` / `text-base` / `text-lg` / `text-xl` / `text-2xl` / `text-3xl`，一个页面里出现的字号不超过 4 档
- 正文用 `text-sm`，页面主标题用 `text-2xl` 或 `text-3xl`，不要更大
- 字重只用 `font-normal` 和 `font-medium`。`font-bold` 只用于页面主标题
- 数字、ID、代码、时间戳一律 `font-mono`
- 正文行宽不超过 `max-w-prose`

### 间距与布局

- 间距只用 4 的倍数（Tailwind 默认刻度），不用任意值
- **每个页面的内容必须包在一个有最大宽度和左右内边距的容器里**，文字和控件不允许贴到视口边缘
- 工作台类页面容器上限 `max-w-screen-2xl`，展示类 `max-w-5xl`
- 分组优先用间距，其次用背景色，最后才用边框。**不许用边框来补救层级不清**
- 同一层级的元素间距必须相等，不同层级的间距必须明显不等

### 表格与列表

- 表格占满所在容器的宽度，不要让窄表格漂在宽区域里
- 表头的对齐方式和列边界必须和该列内容一致。表头之间的间距不能小于内容之间的间距
- 同一列内的所有元素用同一种对齐方式，左边缘对齐。状态标签、图标、文字都不例外
- 数值列右对齐并用 `font-mono`，让数位能上下对齐
- 所有行等高。单行放不下的次要信息（错误详情、超长描述）收进悬浮提示或详情页，不要让某一行比其他行高

### 颜色

- 主色调是中性色。界面主体只用 `background` / `foreground` / `muted` / `border` 这几个语义 token
- **不要用蓝色作为主色**
- 彩色只在两种情况下出现：状态（成功/警告/错误/进行中）、以及数据可视化中承载含义的编码
- 一个页面里承载含义的颜色不超过 3 种
- 亮色和暗色主题必须都能看，且层级关系一致

### 动效

- 只做状态转换的动效：hover、focus、展开收起、加载。时长 150–200ms
- 不做入场动画、滚动触发动画、视差
- 组件库自带的过渡效果要保留，不要覆盖掉

## 不许出现的东西

以下是生成式界面反复出现的默认反射，一律不要：

- 居中大标题配一行灰色副标题，下面跟一排等宽图标卡片
- 装饰性渐变、光晕、模糊色块、玻璃拟态、彩色描边
- 卡片套卡片
- 普通信息也套上圆角标签（badge/pill）。标签只用于真正的状态
- 一排除了数字不同、其余完全一样的指标框，尤其是当这些数字之间本该有关系时
- 全大写加宽字距的小标题
- 尺寸或风格不统一的图标，以及纯装饰性的图标
- 深色导航栏配纯白内容区，中间没有任何视觉过渡
- 空状态只放一句「暂无数据」，不给下一步操作
- 加载时页面跳动。有骨架屏就用骨架屏，尺寸要和真实内容一致
- 界面上出现占位假数据（Lorem ipsum、张三、example.com、随便编的数字）

**但也不要为了躲开这些就做成一片空白。** 克制指的是层级精确、排版讲究、对齐严格，不是「全白 + 细线 + 大留白」。

## 交付前自检

页面写完后，自己逐条过一遍。发现问题就改，改完重新检查。
**自检过程不要输出给我，直接交付改好的代码。**

可判定项（这些必须全部为「是」）：

1. 需求里提到的每一个区块都真实存在于页面上吗？（漏掉页脚、漏掉某个按钮，是最常见的失败）
2. 脚手架或模板的残留内容都清干净了吗？
3. 内容有最大宽度容器和左右内边距吗？
4. 所有组件都来自 `components/ui/` 吗？有没有手写了某个组件库已有的东西？
5. 有没有新增任何自定义 CSS、自定义字号、自定义颜色值？
6. 页面里出现了几种字号？超过 4 种就合并
7. 表格：占满容器宽度了吗？表头和列内容对齐吗？同一列的元素左边缘齐吗？所有行等高吗？
8. 窄屏下有没有横向滚动条或文字逐字换行？
9. 亮色和暗色主题都看过了吗？
10. 有没有假数据残留？

需要判断的项：

11. 只看第一屏，使用者能不能立刻知道这个页面是干什么的、下一步该点哪里？
12. 有没有哪个边框、背景、图标、标签、段落，删掉之后不损失任何信息或功能？有就删掉
13. 每个区块是不是都在回答一个新问题？

## 如何修改本文件

发现生成结果不对时，**改这个文件，不要只改那一次的页面**。

新增规则前先问：

- 这条能写成是非题吗？写不成就重写，直到能
- 这条只对这一个页面成立，还是对以后所有页面都成立？只对一个的不要往里加
- 这件事能不能交给 Tailwind 配置、shadcn 组件、或者 lint 规则去强制？能的话去改那些，不要写在这里

规则宁少勿滥。这个文件里每一条都应该是被真实失败换来的。
